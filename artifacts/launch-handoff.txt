HOST CONFIGURATION REQUIRED BEFORE LAUNCH
Database: current settings actively use BASE_DIR/db.sqlite3. Persist and back up
that file, and test restoration. For PostgreSQL, install the driver and configure
the DATABASES setting before migration; the commented example is not active and
DB_* environment variables alone do not switch the current database backend.
Preserve customer rows, UUID references, and media paths when migrating.

Environment: DJANGO_DEBUG=False; long random SECRET_KEY; ALLOWED_HOSTS set to
the exact hostnames; SITE_BASE_URL=https://the-real-host; CSRF_TRUSTED_ORIGINS
set to the exact HTTPS origin(s). Supply secrets outside source control. The
local .env/SECRET_KEY was deliberately not changed.

HTTPS: provision a certificate and redirect HTTP. Set SECURE_SSL_REDIRECT=True,
SESSION_COOKIE_SECURE=True, CSRF_COOKIE_SECURE=True. Set SECURE_HSTS_SECONDS
after verifying HTTPS (start with a short value such as 3600). HSTS subdomains
and preload require a deliberate domain-wide decision, not automatic enabling.
Behind a TLS-terminating trusted proxy, configure SECURE_PROXY_SSL_HEADER in
host settings only if the proxy strips/replaces untrusted incoming headers;
otherwise Django may see HTTP and redirect repeatedly. Verify this on the host.

Application/static: provide a production WSGI/ASGI server and host configuration;
do not use runserver or the rehearsal server for deployment. Current static
settings are /static/ -> BASE_DIR/staticfiles, sources BASE_DIR/static.
Run python manage.py collectstatic --noinput on the release, then serve that
directory through the host web server with correct MIME types.

Uploads: /media/ -> MEDIA_ROOT (default BASE_DIR/media); provide persistent,
writable storage, backups and an independent web-server/CDN route. Disable
script execution, serve correct image MIME types, and allow image uploads within
the app's size limit. collectstatic does not collect uploaded product images.

Email: provide EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend,
EMAIL_HOST/PORT, EMAIL_HOST_USER/PASSWORD, EMAIL_USE_TLS or EMAIL_USE_SSL as
required, DEFAULT_FROM_EMAIL, and STAFF_NOTIFICATION_RECIPIENTS. First verify
with an explicitly authorized test inbox as the ONLY recipient. External SMTP
delivery/spam placement and domain sender configuration are not verified here.

Schedule: run the following every minute from the project directory, using the
production virtualenv and a service account with database/log access:
python manage.py process_notifications --limit 100
Use cron/systemd/Task Scheduler supplied by the host; capture failures in logs,
monitor the failed-notification queue, and verify execution while logged out.
Defaults: unattended Received orders after 10 minutes; approved reservations
within 60 minutes. Command execution and reminder logic are tested locally;
host scheduling, service-account permissions and unattended operation are not.

Payments: JazzCash manual verification is locally tested. The live method is
enabled; the cafe must confirm ownership/correctness of the receiving account.
Easypaisa manual verification is tested with a synthetic receiver only; the live
method remains disabled until a real receiving account is configured in Admin.
Cash delivery/pickup and QR dine-in regressions are locally tested. Card checkout
remains disabled: no sandbox credentials supplied. Configure merchant-supported
credentials/webhook and verify sandbox payment, callback authenticity and amounts
before enabling. No real-money transfer was attempted.
